# t-SNE 特征分析：这个模型到底把哪几类混在了一起

README 里那张 t-SNE 图只占了十几行，四条结论一带而过。这篇文档是那次分析的完整记录，回答三个问题：

1. 为什么特征要从检测头**前一层**取，取错层会得到什么
2. 混淆的那几类在二维平面上具体是怎么叠的
3. 长尾分布拖垮的是哪几类，图上能不能看出来

图在 `docs/figures/tsne-features.png`，脚本在 `src/tsne_features.py`。下面提到的每个指标都出自 README 的实测表，没有一个是估的。

---

## 0. 先说清楚为什么要做这一步

训练完拿到的数字是这样的（测试集 230 张、370 个实例）：

| | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 |
| :--- | :--- | :--- | :--- | :--- |
| 全类平均 | 0.745 | 0.604 | 0.656 | 0.331 |

Precision 0.745 比 Recall 0.604 高出 0.14。这个差值的方向很重要：模型报出来的框基本靠得住，问题在于**该报的没报**。混淆矩阵上最亮的非对角格子是油斑和水斑互判，另外有相当数量的真实缺陷被判成了背景。

到这一步，常规指标能告诉我的就到顶了。它说"油斑和水斑分不开"，但分不开这件事发生在哪一层？有两种完全不同的可能：

- **可能 A**：骨干网络其实已经把两类的特征分开了，是检测头的分类分支没学好，或者 NMS、置信度阈值这些后处理环节把它们搅在了一起。
- **可能 B**：骨干网络输出的特征本身就重叠，两类在特征空间里根本没分开，检测头拿到的是一份已经糊了的输入，再怎么训也回天无力。

这两种情况的处方完全相反。A 该调头和后处理，B 该改特征提取（注意力模块、更强的增强、重采样）。**混淆矩阵区分不了 A 和 B，因为它统计的是最终输出。** 想区分就得把中间特征掏出来直接看，这是做 t-SNE 的唯一动机，不是为了配图好看。

## 1. 为什么取检测头前一层

### 层的位置

Ultralytics 的模型是一个 `nn.Sequential` 风格的模块列表，最后一个元素是 `Detect` 头：

```python
target_layer = net.model[-2]      # 检测头是 model[-1]，往前一层拿特征
handle = target_layer.register_forward_hook(hook)
```

`model[-1]` 是 `Detect`，`model[-2]` 是它前面最后一个共享模块。选 `[-2]` 不是随手选的，理由有三条。

### 理由一：检测头的输出已经被任务坍缩过了

`Detect` 干的事是把特征图映射成边框回归量和类别打分。它的输出维度由 `nc`（这里是 10）和 DFL 的 reg_max 决定，跟"这个缺陷长什么样"已经没有直接关系了，只跟"它是第几类、框在哪"有关。

在这上面做 t-SNE，得到的图基本等价于把分类打分向量画出来。同一类的点当然会聚在一起（因为它们的 argmax 相同），但这是**同义反复**：模型判成一类的东西在"模型的判断"这个空间里自然是一类。这种图看着很漂亮，簇分得干干净净，但它证明不了任何事。它测的是模型的自信程度，不是特征的可分性。

换句话说，在头的输出上做降维，**没法区分上面说的可能 A 和可能 B**，因为头之后的表示已经被答案污染了。

### 理由二：`[-2]` 是最后一份"还没被答案污染"的表示

`model[-2]` 的输出是骨干加颈部一路卷积、上采样、拼接之后交给头的东西。它对每个类别都是中立的，没有哪个通道被指定去负责"油斑"。如果两类在这一层就已经重叠，那检测头拿到的输入是不可分的，问题定位在特征提取，可能 B 成立。如果这一层分得很开而最终指标却很差，就该去查头和后处理，可能 A 成立。

**取 `[-2]` 的意义就是让这张图具备否证能力。** 结果是图上确实有几类糊在一起，所以结论落在 B。

### 理由三：再往前取会丢掉多尺度融合的结果

也可以取更浅的层，比如骨干的 P3、P4、P5 输出。这样做的问题是浅层特征偏纹理和边缘，还没经过 FPN/PAN 的跨尺度融合，画出来的图更多反映"这块区域的局部纹理长什么样"，而不是"模型最终依据什么做判断"。而这次要诊断的恰恰是模型的判断依据，所以要取融合之后、决策之前的那一层，也就是 `[-2]`。

### 一个诚实的说明

本地环境没装 ultralytics，所以我**没有**去实测 `net.model[-2]` 的具体类名和通道数，这篇文档里也不会写。能确认的只有代码里写死的事实：钩子挂在倒数第二个模块上，`Detect` 是倒数第一个。不同的 YOLOv8 变体（n/s/m/l/x）这一层的通道数不同，脚本不依赖这个数字，因为后面会做全局平均池化把空间维度压掉。

## 2. 从一个标注框到一个特征向量

这一段是实现细节，但有两个决定会直接影响图长什么样，值得写清楚。

### 按标注框裁，不是整图前传

一张 2048×2048 的原图上可能有多个缺陷，整图前传只能得到一个特征向量，没法归到某一类。所以脚本是**逐标注框**处理：读 YOLO 格式的标签行（`类别 cx cy w h`，归一化），换算成像素框，从原图裁出这块区域，单独走一次前传。

```python
crop = crop.resize((args.imgsz, args.imgsz), Image.BILINEAR)
```

裁完统一 resize 到 1024（和训练时的 `imgsz` 一致）。这一步是必须的：不同缺陷的框大小差好几个数量级，不统一尺寸的话特征图的 H、W 不同，池化之后向量长度虽然一样，但感受野的相对覆盖面积差太多，等于在比较不同尺度下的东西。

代价是**长宽比被拉变形了**。月牙弯这种细长缺陷被拉成方的，形状信息有损失。这是个已知的取舍，换成 letterbox 填充会更规范，当时没做。

### 太小的框直接丢掉

```python
MIN_CROP_PX = 8   # 裁剪框太小的样本特征没有意义，直接丢掉
```

原图上不到 8 像素的框，放大到 1024 之后是一片插值出来的糊块，特征向量反映的是插值算法而不是缺陷。留着只会往图上加噪点，所以丢掉。这意味着**图上的点数会略少于表里的实例数**，尤其是异物这类小目标。

### 全局平均池化

```python
vec = out.detach().float().mean(dim=(2, 3)).squeeze(0).cpu().numpy()  # (1,C,H,W) -> (C,)
```

钩子抓到的是 `(1, C, H, W)` 的特征图，在 H、W 上取均值压成 `(C,)`。GAP 丢掉了空间位置信息，只保留"哪些通道被激活了、激活多强"。对这个任务是合适的：要问的是"这块缺陷的特征模式是什么"，而不是"缺陷在框里的哪个位置"。

## 3. 为什么先 PCA 再 t-SNE

```python
def reduce_dims(X, args):
    X = StandardScaler().fit_transform(X)
    n_comp = min(args.pca_dims, X.shape[0], X.shape[1])
    if n_comp < X.shape[1]:
        X = PCA(n_components=n_comp, random_state=args.seed).fit_transform(X)
    perp = min(args.perplexity, max(5.0, (X.shape[0] - 1) / 3))
    return TSNE(n_components=2, perplexity=perp, init="pca",
                random_state=args.seed).fit_transform(X)
```

三层处理，每层都有原因。

**StandardScaler**：卷积特征各通道的数值范围差得很远，有的通道均值接近 0，有的常年在几十。t-SNE 用的是欧氏距离，不做标准化的话距离几乎由那几个数值大的通道独占，其余通道的信息被淹没。

**PCA 到 50 维**：高维空间里欧氏距离会退化（维度灾难，各点间距趋于相等），t-SNE 依赖的邻域关系跟着变得不可靠。先用 PCA 压到 50 维，把方差集中到主要方向、顺手滤掉一部分噪声，再交给 t-SNE。50 这个数是 t-SNE 原论文和 sklearn 文档里的常用起点，不是调出来的。

**perplexity 自适应**：

```python
perp = min(args.perplexity, max(5.0, (X.shape[0] - 1) / 3))
```

perplexity 大致对应"每个点考虑多少个邻居"，sklearn 要求它小于样本数。默认 30，但如果用 `--max-samples` 限制了样本量，或者某个 split 很小，30 会直接报错。`(n-1)/3` 给出一个跟样本量挂钩的上限，下限 5 兜住极端情况。**用不同的 `--max-samples` 跑出来的图不能直接对比**，因为 perplexity 可能不同。

**`init="pca"` 和固定 `random_state`**：t-SNE 是随机优化，随机初始化下每次跑出来的图长得不一样（簇的位置、朝向都会变）。用 PCA 初始化加固定种子，同样的输入能复现同样的图。这是 sklearn 现在推荐的默认做法，也让这张图可以被别人重跑核对。

## 4. 二维图上读出来的东西

先说一个容易踩的坑：**图例的编号和 README 类别表的编号差 1**。图例是 `1_chongkong` 到 `10_yaozhe`，1-indexed；README 和 `data/gc10det.yaml` 里冲孔是类别 0。对照的时候图例 `n_xxx` 对应类别 `n-1`。

图是在测试集上跑的（`--split` 默认 `test`），所以各类的点数应该接近表里的测试实例数：冲孔 35、焊缝 56、月牙弯 23、水斑 27、油斑 67、丝斑 89、异物 33、压痕 11、折痕 7、咬折 22，合计 370。这个对应关系下面会用到。

按图上的形态，十类可以分成三种状态。

### 状态一：自己占一块地，边界清楚

**焊缝（`2_hanfeng`，绿）** 在右下角，一个又大又紧的团，x 大约 15 到 23、y 大约 −20 到 −29，和其他所有类之间隔着一大片空白。只有一个折痕的点落在它上边缘（约 16.5, −19）。

**月牙弯（`3_yueyawan`，红）** 在正上方，紧凑的一小簇，x 约 −11 到 −6、y 约 20 到 27。边上挤进来一个绿点（约 −11, 19）。

**冲孔（`1_chongkong`，橙）** 紧贴在红簇下面，x 约 −12 到 −4、y 约 14 到 18，左边还有一小撮卫星点（x 约 −15 到 −13）。

这三类在表里的表现是：

| 类别 | P | R | mAP@0.5 |
| :--- | :--- | :--- | :--- |
| 冲孔 | 0.967 | 1.000 | 0.978 |
| 焊缝 | 0.773 | 0.946 | 0.940 |
| 月牙弯 | 0.841 | 0.913 | 0.942 |

**图和表完全对得上。** 这三类都是几何形状明确的缺陷：冲孔是规则圆孔，焊缝是贯穿的直线条纹，月牙弯是板材边缘的弧形缺口。它们的判别依据是形状和边缘，不是纹理，卷积网络对这类特征提取得很好，所以在特征空间里就已经彼此分开，检测头只需要做一次简单的线性划分。

值得注意的是**冲孔和月牙弯的簇挨得很近但没混**（一个 y 在 14 到 18，一个 y 在 20 到 27，中间有间隙）。它们在图像上都表现为"板材上少了一块"，特征相近是合理的，但边界仍然清楚，指标也都在 0.94 以上。这说明模型区分它们靠的是缺口形状（圆 vs 弧）而不是"有没有缺口"。

### 状态二：糊成一团，谁也不挨着谁的边界

这是这张图最有价值的部分。图的中间偏右有一大片混合区，四类挤在里面：

**丝斑（`6_siban`，粉）** 是最大的一片，x 约 7 到 23、y 约 −8 到 3，还拖出一条细带往左延伸（沿 y 约 −1 到 −5，穿过 x 约 −10 到 7）。89 个实例，是测试集里最多的一类，占地面积也最大。

**油斑（`5_youban`，棕）** 是全图**最散的一类**，根本没有簇的形状，从 x 约 −22 一直抹到 15、y 约 −7 到 19，像一层薄雾铺在整个中部。它左边压着咬折，中间和异物缠在一起，右边伸进丝斑的地盘。

**异物（`7_yiwu`，灰）** 在正中间，x 约 −17 到 1、y 约 −5 到 5，**没有任何属于自己的边界**，整片都和棕、粉交替出现，左边直接融进咬折的边缘。

**水斑（`4_shuiban`，紫）** 裂成了两块：一部分散在中部的棕灰粉混合区里（y 约 0 到 7），另一部分是 x 约 5 到 7、y 约 −10 到 −14 的一个紧簇，而这个紧簇里还混着棕点和青点。

对应的指标：

| 类别 | P | R | mAP@0.5 | 测试实例 |
| :--- | :--- | :--- | :--- | :--- |
| 水斑 | 0.674 | 0.778 | 0.735 | 27 |
| 油斑 | 0.696 | 0.376 | 0.524 | 67 |
| 丝斑 | 0.701 | 0.500 | 0.616 | 89 |
| 异物 | 0.760 | 0.193 | 0.376 | 33 |

**这就是可能 B 的直接证据。** 混淆矩阵告诉我油斑和水斑互判最严重，t-SNE 图告诉我这件事发生在特征层：油斑的点和水斑的点在二维平面上根本没有可分的边界。检测头拿到的输入已经是混的，它做不出正确的划分不是因为它没学好，而是因为**输入里就没有足够的区分信息**。

再往下看，图里的重叠比混淆矩阵透露的更多：**异物也在这团里，而且是最没形状的一个**。异物的 Recall 只有 0.193，是全类最低。混淆矩阵把这解释成"大量真实缺陷被判成背景"，图给出了机理：异物的特征向量散布在油斑和丝斑的分布内部，既然它连和其他缺陷都分不开，那和"什么都不是"的背景之间自然也没有清晰的界线，置信度上不去，卡阈值的时候就被丢了。

**为什么是这四类混？** 它们的共同点是**面状污渍类缺陷**：油斑、水斑是液体残留的浅色斑块，丝斑是细密的丝状纹理，异物是压进板材表面的杂质。三个特性叠在一起：

1. **边界是渐变的**，不像冲孔那样有硬边缘。卷积网络在这里没有稳定的边缘响应可以依赖，只能靠纹理统计量，而纹理统计量对这几类本来就接近。
2. **标注本身带主观性**。一片浅色残留到什么程度算油斑、什么程度算水斑，不同标注者的判断不一致，训练标签里就有噪声。特征提取器学的是被噪声污染过的目标，学出来的表示自然也是混的。
3. **尺度跨度大**。同一类的斑块面积可以差十倍，加上第 2 节说的强制 resize 变形，同类内部的特征方差被进一步放大，簇就散开了。

油斑散成一层雾而丝斑还算聚成一团，这个差异也说得通：丝斑有一致的丝状纹理（虽然细，但方向和密度稳定），油斑除了"浅色一片"之外没有稳定的可依赖特征。这正好对应表里丝斑 mAP 0.616 高于油斑 0.524。

### 状态三：点太少，连簇都形不成

**压痕（`8_yahen`，橄榄绿）** 全图只有寥寥几个点，分两处：（−1 到 1, 6.5 到 7）落在棕色雾里，（12 到 15, −3 到 −7）挂在粉色区的右下边缘。**没有任何聚集形态。**

**折痕（`9_zhehen`，青）** 同样只有几个散点：（−11, 14.3）和（−10.5, 15.5）贴在冲孔的橙带旁边，（5.5 到 6, −15 到 −16）落在水斑那个紧簇里，（16.5, −19）孤零零挂在焊缝团的边上。**也没有簇。**

这两类的点数，目测和表里的测试实例数（压痕 11、折痕 7）在同一量级，考虑到 `MIN_CROP_PX` 会丢掉极小的框，数量是自洽的。

## 5. 长尾具体拖了哪几类

测试集 370 个实例在十类之间的分布是这样的：

```
丝斑 89  ████████████████████████
油斑 67  ██████████████████
焊缝 56  ███████████████
冲孔 35  █████████
异物 33  █████████
水斑 27  ███████
月牙弯 23 ██████
咬折 22  ██████
压痕 11  ███
折痕  7  ██
```

最多的丝斑是最少的折痕的 **12.7 倍**。被这个分布直接拖下去的是队尾两类：

| 类别 | 实例 | P | R | mAP@0.5 | 全类排名 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 压痕 | 11 | 0.715 | 0.364 | 0.409 | 倒数第二 |
| 折痕 | 7 | 0.546 | **0.429** | **0.355** | 倒数第一 |

折痕的 mAP@0.5 只有 0.355，是全类最低；Precision 0.546 也是全类最低，比第二低的水斑（0.674）还差 0.13。**Precision 和 Recall 同时垫底，这和第 4 节那几类是不同的病。**

油斑、丝斑、异物的病是"特征不可分"：它们样本不算少（67、89、33），Precision 都在 0.7 上下，模型对它们有稳定的（哪怕是错的）判据，问题是判据区分不开近邻类。

压痕和折痕的病是"**样本量不足以学出任何判据**"。7 个实例，扣掉框太小被丢的，t-SNE 图上就是那么四五个点。这个量级下：

- **模型层面**：网络没见过足够多的折痕变体，学不出这一类的稳定表示。表现为它偶尔能报对（Recall 0.429，不是 0），但报出来的一半是错的（Precision 0.546）。
- **评估层面**：7 个实例意味着**每漏检一个，Recall 掉 14.3 个百分点**。折痕的 0.429 实际上就是"7 个里报中了 3 个"。这个数字的置信区间宽得没法用来做任何比较，说折痕比压痕差 0.05 是没有意义的。

这是长尾问题在指标上留下的双重痕迹：**既让模型学不好，又让"学得多差"这件事无法被可靠测量。**

值得单独说的是**咬折（`10_yaozhe`，蓝）**。它只有 22 个实例，样本量在队尾附近，但在图上它有自己独立的一块地（左侧，x 约 −23 到 −17、y 约 −2 到 5），mAP@0.5 做到了 0.685，比样本量三倍于它的丝斑（89 个，0.616）和油斑（67 个，0.524）都高。它的簇右边缘混进了一些棕点和灰点，所以 Recall 0.545 一般，但整体表现完全不像一个尾部类别。

**咬折这个反例说明了长尾不是唯一变量。** 咬折是板材边缘的折叠变形，有明确的几何形态，22 个样本就够网络学出可分的表示。折痕虽然听起来类似，但它是板面上的浅折印，视觉上更接近纹理变化而非几何变形，7 个样本连方向都摸不清。

所以这份数据上真正的因果链是：**"几何特征明确"决定了这一类能不能学好，"样本量"决定了能学多稳。** 两个条件都满足的（冲孔 35、焊缝 56、月牙弯 23）指标在 0.94 以上；只满足几何条件的（咬折 22）能到 0.685；只满足样本量条件的（丝斑 89、油斑 67）卡在 0.5 到 0.62；两个都不满足的（压痕 11、折痕 7）在 0.4 以下。

## 6. 这张图不能证明什么

t-SNE 特别容易被过度解读，下面几条是这份分析明确不主张的。

**簇之间的距离没有意义。** 焊缝的团离其他所有类都很远，这不代表焊缝的特征"更特殊"。t-SNE 优化的是局部邻域关系的保持，全局的簇间距离在优化目标里基本不受约束。不能因为焊缝离得远就说它和别的类差异更大。

**簇的大小和密度也不能直接读。** t-SNE 会把稠密的区域摊开、把稀疏的区域压紧。油斑铺得广不能直接推出"油斑的类内方差比丝斑大"，只能说"在这份 perplexity 设置下，油斑的邻域结构不支持它收成一个团"。这个结论已经足够支撑第 4 节的论证，不需要更强的版本。

**换参数图会变。** perplexity 变了，簇的形态会变，小的簇可能被合并或打散。这份分析用的是默认 30（受 `(n-1)/3` 上限约束），换成 5 或 50 应该重新看图再下结论。严谨的做法是扫几个 perplexity 值确认结论稳定，当时没做。

**这不是量化指标。** "糊在一起"是肉眼判断。想量化应该算类内类间距离比、silhouette score 或者 kNN 分类准确率这类数字，图只能定性。不过对"定位问题在哪一层"这个目的，定性就够了。

**关于图和脚本的一致性：** `docs/figures/tsne-features.png` 是 2026 年 6 月那次课程设计跑出来的原始输出。仓库里的 `src/tsne_features.py` 是后来按报告记录的方法重写的（原始项目文件已丢失，见 README 的"关于这个仓库"）。两者有可见的细微差别：脚本的图例会带样本数 `(n=...)`，图上的图例没有。**所以别把这张图当成这份脚本的逐字输出**，它是同一方法的那次运行结果。重跑脚本会得到形态一致但图例略有不同的图。

## 7. 结论和下一步

**回答第 0 节的问题：是可能 B。**

瓶颈不在检测框回归，也不在检测头。`model[-2]` 这一层的特征里，油斑、水斑、丝斑、异物四类就已经没有可分的边界了，检测头拿到的是一份混好的输入。压痕和折痕则是另一个问题：样本太少，特征层面连成形的表示都没有。

按这个诊断，值得试的方向有优先级：

1. **提升特征判别性**，针对面状污渍那四类。在颈部加注意力模块（SE、CBAM 之类）让网络学会加权哪些通道，或者引入一个类间的度量学习损失，显式地把油斑和水斑往两边推。这是唯一能动摇"特征不可分"的方向。
2. **处理长尾**，针对压痕和折痕。重采样、copy-paste 增强，或者按实例数给类别加权。但要清楚**这两类的评估指标本身就不可靠**（7 个和 11 个实例），改进之后指标涨了 0.05 说明不了什么，得先把测试集这两类的实例数补上去，否则测不出来。
3. **改 resize 策略**，换成保持长宽比的 letterbox。这一条同时会影响训练和这份分析，成本低，值得先做。
4. **回头审标注**。油斑和水斑的标注一致性如果本来就不高，前三条做到极限也有天花板。抽一批双人复核，把标注一致率量出来，才知道 0.656 的 mAP 里有多少是模型的问题、多少是标签的问题。

值得注意的是，**在做 t-SNE 之前我的第一反应是调超参和加训练轮次**。图看完之后这个想法被否掉了：训练曲线在 60 轮后就平了，特征都糊在一起的情况下继续训只会让模型更自信地犯同样的错。这张图省下的是几十个小时的无效调参。

## 复现

```bash
python src/tsne_features.py \
  --weights runs/detect/train/weights/best.pt \
  --data data/gc10det.yaml \
  --split test \
  --imgsz 1024 \
  --out results/tsne-features.png
```

需要数据集按 `data/gc10det.yaml` 的目录结构摆好（数据集和权重都不在仓库里，见 README）。其他可调参数：`--perplexity`、`--pca-dims`、`--max-samples`、`--seed`、`--device`。改了 `--max-samples` 或 `--perplexity` 之后图和这篇文档描述的形态会不同。
